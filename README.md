## 고정 이미지 규격

- 서버 아이콘: `256×256`, PNG/JPG/WebP, 최대 1MB
- PC·모바일 공용 목록 배너: `468×60` (39:5, GIF·WebM 원본 보존) — 일반·프리미엄 공통
- 데스크톱 상세 배너: `1440×480` (3:1)
- 모바일 상세 배너: `750×500` (3:2)
- 배너 공통: PNG/JPG/WebP/GIF/WebM, 각 최대 950KB · GIF/WebM 애니메이션 유지
- Open Graph 공유 이미지: `1200×630`

이미지는 모두 선택 사항입니다. 이미지 없이 서버를 먼저 등록하면 서버명 이니셜 아이콘과 서버별 기본 그라데이션 배너가 적용되고, 운영자센터에서 나중에 교체할 수 있습니다. PNG/JPG/WebP 정지 이미지는 원본 픽셀 크기와 관계없이 실시간 크롭 편집기에서 드래그·확대·가로·세로 위치를 조절한 뒤 각 완성 규격의 WebP로 변환됩니다. 작은 아이콘은 픽셀 선명 확대를 사용합니다. GIF와 WebM은 애니메이션 보존을 위해 완성 규격과 용량을 그대로 검증하며, WebM은 음소거·자동재생·반복 방식으로 출력됩니다. 프리미엄 여부에 따라 별도 이미지를 만들 필요가 없고, 프리미엄은 상단 위치·광고 배지·강조선으로만 구분합니다.

UI 컴포넌트를 변경한 작업은 빌드·린트 통과만으로 완료 처리하지 않습니다. 변경한 화면을 실제 브라우저에서 열고, 드롭다운·팝업·버튼 등 수정한 상호작용을 직접 실행해 런타임 오류가 없는지 더블체크합니다. 드롭다운 변경 시에는 모든 메뉴를 각각 열어 항목 선택, 선택값 반영, 바깥 클릭 닫기, 키보드 탐색과 모바일 폭을 확인한 뒤 검증 완료로 기록합니다.

```bash
pnpm install
pnpm run dev
pnpm run lint
pnpm test
```

서버 브리지 문서와 실기동 보고서는 `minecraft-bridge/README.md`, `BRIDGE_VERIFICATION_REPORT.md`에 그대로 보존되어 있습니다.

## 서버 등록·운영자 CRUD

- D1 `directory_servers`: 제목, 한 줄 소개, 상세 설명, 에디션, 최소·최대 버전, 주소, 포트, 카테고리, 상태, 소유자와 브리지 연결을 저장합니다.
- D1 `server_assets` + R2 `MEDIA`: 아이콘과 배너 4종을 서버측에서 형식·용량·실제 픽셀까지 다시 검증해 저장합니다.
- `POST /api/servers`: 소유자 서버 등록 및 중복 주소 차단
- `GET /api/servers?mine=1`: 현재 소유자가 등록한 서버 조회
- `GET/PATCH/DELETE /api/servers/:serverId`: 상세 조회, 전체 필드 수정, 제목 확인 기반 삭제
- `POST /api/servers/:serverId/assets`: 이미지 5종 저장 및 교체
- `POST /api/servers/:serverId/bridge`: Paper/Bukkit·Velocity 인증 키 발급과 디렉터리 서버 연결
- `/operator`: 서버 정보 수정, 주소 변경 재인증 안내, 브리지 인증 준비와 삭제

배포 환경에서는 Minecraft.kr 이메일 세션에서 검증된 사용자 이메일로 소유권을 판정합니다. 브라우저가 임의로 전달한 사용자 이메일 헤더는 신뢰하지 않습니다. 로컬 미리보기 전용 헤더는 `localhost`와 `127.0.0.1`에서만 허용됩니다. 주소나 포트가 변경되면 기존 브리지 자격 증명을 폐기하고 서버 상태를 다시 `draft`로 되돌립니다. 삭제 시 브리지 키·nonce·백엔드 상태·R2 이미지도 함께 제거합니다.

반복 가능한 회귀 검증은 개발 서버가 실행된 상태에서 `pnpm test:server-crud`로 수행합니다.

## 공개 목록 실시간 갱신

- 공개 서버와 상세 정보는 예시 배열이 아니라 D1의 서버·추천·브리지 텔레메트리·광고·운영진 데이터를 조합합니다.
- 추천 등록, 서버 수정, 이미지 교체, 브리지 인증 또는 텔레메트리 수신 시 Durable Objects WebSocket으로 열린 목록에 변경 이벤트를 즉시 전달합니다.
- WebSocket이 끊긴 환경에서는 30초 폴링으로 자동 전환하고, 연결이 회복되면 다시 실시간 상태로 돌아갑니다.
- 14일 차트는 5분 버킷으로 수집된 실제 접속자 이력을 일별 집계하며 표본이 없으면 임의 그래프를 만들지 않습니다.
- 닉네임 머리는 `mc-heads.net`의 Minecraft 아바타 이미지로 가져오며 실패하면 사이트 내부 기본 아이콘으로 대체합니다.

## 이메일 로그인·서버 소유권

- `/login`은 비밀번호 대신 이메일로 발송한 6자리 일회용 코드를 사용합니다. 코드는 10분간 유효하고 5회 실패 시 폐기되며, 로그인 세션은 해시로 D1에 저장되는 30일 HttpOnly·SameSite Lax 쿠키입니다.
- 메인 헤더는 로그인 세션을 확인해 `OWNER LOGIN`과 현재 이메일을 표시하며, 운영자센터로 바로 이동할 수 있습니다.
- 처음 인증한 이메일은 자동으로 운영자 계정이 생성됩니다. API는 브라우저가 보낸 이메일 헤더를 신뢰하지 않고, Worker가 검증한 세션 이메일만 내부 소유자 헤더로 전달합니다.
- `/operator`의 `서버 관리 양도`에서 대상 이메일을 입력하면 상대 계정의 수락함으로 요청이 전달됩니다. 상대방이 서버 MOTD에 1시간짜리 `[MKR-TRANSFER:…]` 문자열을 넣고 검증해야 양도가 완료됩니다.
- 양도 완료 시 기존 브리지 키, nonce, 백엔드 정보, 실시간 대화 접속권과 기존 소유자의 직통라인 이력을 폐기합니다. 진행 중인 입찰·미결제 낙찰·프리미엄 광고가 있으면 양도를 차단합니다.
- 공개 운영 중인 서버 상세의 `이 서버 주장하기`는 MOTD 문자열 또는 `_minecraft-kr-verify.<서버주소>` DNS TXT 레코드로 실제 통제권을 검증합니다.
- 서버 주장은 기술 인증만으로 즉시 이전되지 않습니다. 서버를 `disputed` 상태로 잠가 기존 운영자의 수정·삭제·경매 참여를 막고, 기존 소유자에게 알린 뒤 `/admin` 총관리자 심사에서 승인 또는 거절합니다.
- 총관리자 승인 시 기존 자격 증명을 전부 회수하고 새 이메일을 단독 소유자로 설정합니다. 같은 서버의 다른 미결 소유권 요청은 자동 종료되며 모든 작업은 감사 로그에 기록됩니다.

운영 이메일 발송에는 `RESEND_API_KEY`, `AUTH_EMAIL_FROM`, 코드 HMAC에는 24자 이상의 `AUTH_CODE_SECRET`이 필요합니다. 로컬에서는 `AUTH_LOCAL_PREVIEW=true`일 때 실제 메일을 보내지 않고 화면에만 미리보기 코드를 표시합니다. 로그인 코드는 이메일·접속 환경 양쪽으로 요청 횟수를 제한하고 원자적으로 1회만 소비합니다.

실제 Minecraft 상태 프로토콜을 응답하는 임시 TCP 서버를 띄워 이메일 로그인→MOTD 양도→제3자 주장→총관리자 승인→기존 권한 회수까지 검증하려면 다음을 실행합니다.

```bash
pnpm test:ownership
```

## 총관리자 시스템

- `/admin`: 서버 제어, 프리미엄 광고, 주소/IP 블랙리스트, 운영자 직통라인, 감사 로그를 한 화면에서 관리합니다.
- 추천수는 정수 강제값, 업타임은 `0-100%` 강제값을 설정하거나 비워 자동 집계값으로 복귀할 수 있습니다.
- 프리미엄 광고는 시작·종료 시각, 노출 등급과 내부 메모를 관리하며 기간이 지난 광고는 자동 비노출됩니다.
- 서버 삭제는 서버 이름 재입력을 요구하고 R2 이미지와 브리지 자격 증명을 제거합니다. 삭제 작업과 사유는 감사 로그에 남습니다.
- 블랙리스트는 서버 주소 또는 IP를 영구/기간제로 차단합니다. 등록·수정·브리지 발급 단계에서도 다시 검사합니다.
- `/operator`의 총관리자 직통라인은 서버별 1대1 대화이며 양쪽 미확인 건수를 별도로 관리합니다.

운영용 OTP 자격 증명은 소스 코드에 저장하지 않습니다. 다음 명령으로 PBKDF2 비밀번호 해시, Base32 TOTP 시크릿과 OTP 앱 등록 URI를 생성한 뒤 출력된 값을 배포 환경 변수에 넣습니다.

```bash
ADMIN_EMAIL="admin@minecraft.kr" pnpm admin:credentials '12자 이상의 강한 비밀번호'
```

필수 운영 환경 변수는 `ADMIN_EMAIL`, `ADMIN_PASSWORD_HASH`, `ADMIN_TOTP_SECRET`입니다. 관리자 세션은 D1에 해시로 저장되는 8시간 HttpOnly·SameSite Strict 쿠키이며, 변경 요청은 동일 출처만 허용합니다. 5회 인증 실패 시 동일 접속 환경을 15분 동안 잠급니다. 로컬 미리보기에서는 `.dev.vars`의 전용 비밀번호와 OTP `000000`만 localhost에서 사용할 수 있습니다.

개발 서버가 실행된 상태의 전체 총관리자 API 회귀 검증은 다음과 같습니다.

```bash
pnpm test:admin-security
```

### 직통라인 실시간 전송

- D1을 대화 이력의 원본으로 유지하고, Cloudflare Durable Objects의 WebSocket Hibernation API로 새 메시지를 즉시 전송합니다.
- 운영자는 선택한 서버 전용 방에, 총관리자는 모든 서버 이벤트를 받는 전역 관리자 방에 연결됩니다.
- 브라우저는 인증된 REST 요청으로 45초짜리 일회용 접속권을 발급받으므로 관리자 세션 쿠키나 운영자 인증값이 WebSocket URL에 노출되지 않습니다.
- 연결이 끊기면 지수 백오프와 무작위 지연으로 자동 재접속하고, 다시 보이는 탭이나 온라인 복귀 시 즉시 연결합니다.
- 서버 삭제 시 해당 서버의 메시지, 대화 상태와 사용 전 실시간 접속권도 함께 제거합니다.

실시간 접속권 재사용 차단과 운영자↔총관리자 양방향 즉시 수신은 개발 서버가 실행된 상태에서 다음 명령으로 검증합니다.

```bash
pnpm test:chat-realtime
```

실시간 접속권과 공개 목록 Durable Object 바인딩·SQLite 클래스 마이그레이션은 `vite.config.ts`에 선언되어 있습니다.

## 주간 프리미엄 경매

Minelist의 추천수와 무관한 최상단 고정 노출 방식은 유지하되, Minecraft.kr은 선착순 판매 대신 주간 공개 경매로 슬롯을 배정합니다.

- 매주 월요일 00:00 KST 시작 광고를 이전 주 월요일부터 일요일 20:00 KST까지 입찰합니다.
- 기본 광고 슬롯은 4개이며 총관리자가 첫 입찰 전까지 슬롯 수, 최소 입찰가와 최소 인상액을 조정할 수 있습니다.
- MOTD·브리지 소유권 인증이 완료되고 `active` 상태인 서버만 참여할 수 있습니다.
- 운영자 계정당 한 주에 한 서버만 입찰할 수 있고, 입찰 후에는 최소 인상액 이상으로 올릴 수만 있습니다.
- 금액 내림차순으로 낙찰하며 동일 금액은 해당 금액에 먼저 도달한 서버가 우선합니다.
- 낙찰 후 총관리자가 결제를 확인하면 다음 주 프리미엄 노출이 예약됩니다.
- 미결제 낙찰을 포기 처리하면 차순위 인증 서버가 자동 승계합니다.
- 마감·낙찰·결제 확인·포기와 규칙 변경은 모두 관리자 감사 로그에 기록됩니다.

실제 인증 서버 생성부터 입찰·조기 마감·결제 확인·프리미엄 예약까지의 로컬 회귀 검증은 다음 명령으로 수행합니다.

```bash
pnpm test:premium-auction
```

## 배포 전 운영 체크리스트

1. `drizzle/0000`부터 `drizzle/0009`까지 운영 D1에 순서대로 적용합니다.
2. 운영 R2 `MEDIA`, D1 `DB`, Durable Object `CHAT_ROOMS`·`DIRECTORY_LIVE` 바인딩을 연결합니다.
3. `.dev.vars.example`의 인증·메일·관리자 OTP·브리지 비밀을 운영 비밀 저장소에 넣고 모든 로컬 미리보기 플래그를 끕니다.
4. 외부 본인인증 제공자의 성공 결과를 총관리자 본인인증 심사 화면에 공급합니다. 인증되지 않은 계정은 프리미엄 입찰이 서버측에서 거절됩니다.
5. `ALLOW_PRIVATE_BRIDGE_VERIFY=false`를 유지하고 실제 공개 DNS/MOTD에서 브리지·양도·서버 주장 인증을 점검합니다.
6. `pnpm lint`, `pnpm exec tsc --noEmit`, `pnpm test`와 여섯 개 API/실시간 회귀 명령을 모두 실행한 뒤 배포합니다.
